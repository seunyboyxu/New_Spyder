# Classic ESP32 + PCA9685 setup

This fork's main firmware and motor tester target an HW-394 / ESP-32D-style
classic ESP32 board driving eight servos through a PCA9685. No Sesame distro
board is needed. The OLED remains a 128x64 I2C SSD1306 at address `0x3C`.

## Wiring

| Connection | Destination |
| --- | --- |
| ESP32 GPIO21 | PCA9685 SDA and OLED SDA |
| ESP32 GPIO22 | PCA9685 SCL and OLED SCL |
| ESP32 3V3 | PCA9685 VCC (logic) and 3.3V-compatible OLED VCC |
| ESP32 GND | PCA9685 GND, OLED GND, servo-supply ground |
| External regulated 5V, at least 3A | PCA9685 V+ (servo power) |

Power the ESP32 over USB for bench testing. Do not run servo power through its
USB connector or 3V3 pin. Use common ground. Keep PCA9685 address jumpers open
for `0x40`, and ensure OE is low (check your breakout's pull-down). Keep I2C
pull-ups at 3.3V for the ESP32. These instructions do not cover powering the
ESP32 from a battery; use a suitable regulated board supply for untethered use.

| PCA9685 channel | Servo |
| --- | --- |
| 0 | R1 |
| 1 | R2 |
| 2 | L1 |
| 3 | L2 |
| 4 | R4 |
| 5 | R3 |
| 6 | L3 |
| 7 | L4 |

Channels 8–15 are unused and disabled on startup. Channel numbers are not GPIOs.
Check your breakout's signal / V+ / GND markings before connecting servos.

## Arduino IDE

1. Install **esp32 by Espressif Systems**. Select **ESP32 Dev Module** and the
   correct USB port. The build was checked with ESP32 core **2.0.17**.
2. Install **Adafruit PWM Servo Driver Library**, **Adafruit BusIO**,
   **Adafruit SSD1306**, and **Adafruit GFX Library**, accepting dependencies.
   `ESP32Servo` is no longer needed by either sketch.
3. Put `sesame-firmware-main.ino`, `face-bitmaps.h`, `movement-sequences.h`, and
   `captive-portal.h` together in a folder named `sesame-firmware-main`.
   Keep the motor tester in its own sketch folder; do not add it to this sketch.
4. Upload and open Serial Monitor at **115200 baud**.
5. Join **Sesame-Controller**, password **12345678**, then open **http://192.168.4.1**.
   The existing AP/network settings in the sketch can be customized.

## Calibration and behavior

First run the [motor tester](debugging-firmware/README.md) with servo horns
removed. Both sketches use **50Hz**, matching channel assignments, and the
original **732–2929 microsecond** pulse range. That range may exceed your
servos' limits: check their specifications and adjust `MIN_PULSE` / `MAX_PULSE`
in BOTH sketches before testing endpoints. Main firmware retains per-servo
subtrim, angle clamping, movement delays, and all animation sequences.

The main firmware disables all outputs during initialization before bringing up
WiFi. If no PCA9685 is detected it prints an error and halts; fix wiring/address
and reset. Hardware may retain outputs across an ESP32-only reset until the
initialization code runs; disconnect servo power while changing wiring.

The web controller's STOP behavior is unchanged: it stops the current command
and movement routines may return to a standing pose. It does not turn servo
power off or guarantee limp joints. The tester's `stop` disables all PWM outputs
but also leaves power connected.

An ESP32 compile verifies the build, not physical travel, power capacity, OLED
operation, or mechanical fit. Check those on the assembled hardware before
running walking sequences. The PCA9685 board may require a custom mount.
